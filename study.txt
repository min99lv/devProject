1. 사용자가 페이지 입력
http://localhost:88/auth/register

2. 라우팅 (app/Config/Routes.php)
// get요청이  /auth/register 로 오면 AuthController의 register메소드 실행
$routes->get('/auth/register', 'AuthController::register');

3. 컨트롤러 (app/Controllers/AuthController.php)
// 뷰 페이지 렌더링
public function register()
{
    return render('auth/register');  
}

4. render() 함수(app/Helpers/render_helper.php)
메인 레이아웃 파일을 열고 그안에 구체적인 뷰파일 로드
layouts/layout.php (전체 구조)
├─ Header
├─ Nav
├─ $content ← auth/register.php 삽입
├─ Footer

5. 뷰 (app/Views/auth/register.php)
폼 입력 후 회원가입

6. 라우팅 (app/Config/Routes.php)
$routes->post('/auth/storeRegister', 'AuthController::storeRegister');
7. 컨트롤러
AuthController.php - storeRegister 메서드
사용자가 입력한 데이터를 받기 -> 서비스 호출 -> 결과에 따른 처리


8. 서비스(app/Services/AuthService.php)
c->insert()
r->find()
u->update()
d->delete()
// where 필트 = 파라미터 첫번째행 반환환
where('필드', '파라미터')->first()

9. 모델 - 디비 접근
디비 저장

10. Entity
Model에서 $returnType = Users::class;로 지정하면
DB에서 받은 데이터가 자동으로 Users 객체로 변환
 
Request  
 → Routes  
   → Controller  
     → Service  
       → Model  
         → Database  
       ← Entity(결과)  
     ← Service 결과  
   ← Controller Response  
← View (HTML)

2025-12-10

1. getFlashdata() =  임시데이터생명주기
- 설정 : redirct()->with('error', $message) 시점에 저장
- 사용 : session()->getFlashdata('error')로 읽음
- 삭제 : 새로고침하면 사라짐

2. CSRF - 다른 사이트에서 사용자 몰래 요청을 위조하는 공격
- csrf_field() : 폼 요청마다 난수 토큰을 자동 삽입해서 요청 위조를 방지

3. form에 input data를 보낼때 보안 문제
- csrf 공격 - csrf_field()
- xss 공격 - esc()
- sql injection - Prepared Statement(SQL과 데이터가 완전히 분리된 구조)
- 비밀번호 평문 저장 - password_hash()
- 입력값 검증 부재 - Validation

4. 자주사용하는 helper 함수 
- session() - 세션 객체 직접 호출
- redirct() - 리다이렉트 편하게 사용
- esc() - 출력시 xss 방지 
- old() - 폼 입력 실패 시 기존 입력값 유지
- service() - 만든 객체를 가져올때
- csrf_field() - CSRF 보호 input 자동 삽입
- form_open(), form_close() 폼 태그 자동 생성
- url_to() 라우트 기반 URL 생성 

5. DTO 생성
- Data Transper Object 계층 간 통신 : 요청 데이터를 객체로 변환해서 전달  

7. 비밀번호 해싱 
- password_hash($password, PASSWORD_DEFAULT) : 암호화
- password_verify($password, $hash) : 검증
- 단방향 암호화(복호화 불가능)

8. render 커스텀 함수 
Layout을 포함하여 뷰를 렌더링
뷰 파일 이름, 뷰에 전달하는 데이터, 옵션
옵션 : cache, saveData, strictVars
- cache: 화면을 일정 시간 동안 저장해서 다시 만들지 않기
- saveData: view에 넘긴 데이터를 다음 view에서도 유지할지
- strictVars: 없는 변수를 사용하면 에러를 낼지

9. 세션체크를 항상 하는방법
- App\Filters에 AuthCheckFilter 클래스 작성 (세션 체크 로직)
- Config\Filters에 alias 등록 후 필터 적용 경로 지정
  └─ $aliases: 필터 이름 매핑
  └─ $filters: 적용할 경로 명시 (dashboard/*, admin/* 등)
- 지정된 경로 접근 시 자동으로 세션 체크
  └─ 세션 없으면 /auth/login으로 리다이렉트
  └─ 세션 있으면 Controller 실행
